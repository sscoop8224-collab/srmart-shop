# 쇼핑앱 디자인 재정비 진행표

> 화면ID는 `docs/SHOP_SCREENS.md` 와 같다(S01~S43) + 목업의 「제안」(P01~P05).
> **1단계(2026-11-11)는 「목업 반영」 칸만 채웠다.** 목업은 대표님 승인 전까지 정본이 아니다 —
> 승인 전에는 앱 코드(src)를 고치지 않는다.

## 칸의 뜻

| 칸 | 채우는 때 | 적는 것 |
|---|---|---|
| 목업 반영 | 목업(`C:srmartsrmart-shop-mockupindex.html`)에 그 화면이 있을 때 | ✅ |
| 앱 반영 | 앱 코드에 새 디자인을 넣고 빌드했을 때 | 커밋 해시 |
| 비교사진 밝게 / 어둡게 | `docs/shots/compare/<ID>_light.png` · `_dark.png` 를 만들었을 때 | ✅ |
| 상태 | | `목업` → `작업중` → **`완료`** (제안 줄은 `제안` → 채택되면 `목업`, 버리면 `버림`) |

## 🔴 「완료」는 기계가 확인한다 — `npm run check:progress`

`상태` 가 **완료** 인 줄은 아래가 **모두** 있어야 통과한다. 하나라도 없으면 **커밋이 막힌다**
(로컬 git pre-commit 관문 — 설치: `cp scripts/hooks/pre-commit .git/hooks/pre-commit`).

1. `docs/shots/compare/<ID>_light.png` 와 `<ID>_dark.png` — **목업과 앱을 나란히 놓은** 비교 사진
2. `docs/shots/app/<ID>_light.png` 와 `<ID>_dark.png` — 고친 뒤 앱 사진
3. 그 앱 사진이 `docs/shots/before/<ID>_light.png`·`_dark.png`(고치기 전 사진)와 **바이트가 달라야** 한다
   (sha256 비교) — 옛 사진을 그대로 복사해 「완료」로 적는 것을 막는다.

그리고 `SHOP_SCREENS.md` 의 화면ID가 이 표에 **하나도 빠지지 않아야** 한다(화면이 사라지는 것을 막는다).

🔴 **사진이 있다고 디자인이 맞다는 뜻은 아니다.** 검사기는 「찍었는가·바뀌었는가」만 본다.
맞는지는 비교 사진을 사람이 보고 판단한다.
