## 🔴 이 묶음에서 찾아 고친 결함

1. 🔴 **(운영 앱에도 있다) 주문 완료 화면의 금액이 틀렸다.** 결제 금액(할인·배송비 반영)을 「상품 금액」으로 적고, 배송비를 **늘 「무료」** 로 적었다 —
   배송비 3,000원을 낸 손님에게도. 줄 금액도 단가 × 수량이라 **박스·무게 상품이 틀렸다**.
   → 결제 화면이 보여 준 「결제 금액」 칸 값(상품 금액·쿠폰·포인트·배송비)을 그대로 넘겨 보인다(`summaryOf`). 🔴 **서버로 보내는 값은 바뀌지 않았다**
   (App 의 `createOrder` 는 고른 칸만 보낸다 — `summary` 는 안 간다). 줄 금액은 장바구니와 같은 `getItemPrice`.
   (카카오페이가 아직 시험 CID 라 운영에서 이 화면까지 오는 손님은 없다.)
2. (이번 밤 묶음 2 코드) **상세의 「장바구니 담기」 단추가 검색 결과의 「담기」와 같이, 구역(`.sec`) 여백을 받아 한 줄에서 아래로 밀렸다** — 단추 이름(`.ui-btn.sec`)과
   구역 이름(`.sec`)이 겹쳤다. 구역 규칙에서 단추를 뺐다(`.v2 .sec:not(.ui-btn)`).
3. (결함 아님 — 옮기며 피한 것) App.css 의 옛 `.pd-cart-bar` 규칙은 PC 폭에서 바를 본문 안에 놓는다(옛 모양). 새 바는 목업처럼 늘 아래에 고정이라
   이름을 `pd-bar` 로 바꿔 그 규칙을 안 받게 했다(F11 검사기는 두 이름을 다 본다).
4. (검사기) **회전 검사기의 「스크롤이 맨 위로 튐」 자가 시험이 못 잡고 있었다** — 묶음 2 부터 태블릿에서 상품 8개가 4칸 두 줄이라 홈이 한 화면을 안 넘어 **스크롤이 아예 안 생겼다**
   (그래서 그 검사는 늘 「스크롤 0」 이었다). 회전 검사에 상품 32개를 주도록 했다 → 자가 시험 5/5.

## 목업과 다르게 둔 곳 — 목록

1. **사진 넘김·썸네일** — 앱은 상품 목록에서 사진을 **한 장만**(`image`) 받는다(App 이 `images: []` 로 둔다). 그래서 지금은 점·썸네일이 없다.
   여러 장이 있는 상품은 서버가 `images` 를 실어 줄 때 그대로 보인다(코드는 넣어 두었다). 🔸 서버 응답에 사진 목록을 넣을지 — 대표님 결정.
2. **행사 딱지(2+1)** — 묶음 2 와 같은 이유로 상세에서도 상품에 `eventLabel` 이 있을 때만(지금 목록 응답에는 없다). 행사가가 장바구니에 어떻게 들어가는지 정해지면 같이.
3. **재고** — 서버가 `stock_state`(in_stock/low/soldout)·`stock_left` 를 주면 그대로, 없으면(지금 서버) 숫자로 **같은 판정**(10개 이하 「○개 남음」, 0 「품절」). 숫자는 안 보인다.
4. **리뷰 쓰기(S05)** — 목업은 제목 줄이 있는 따로 화면으로 그렸다. 앱은 **상세 그대로** 리뷰 칸 위에 별점·내용 칸을 펼치고, 바가 「취소 · 리뷰 등록」으로 바뀐다
   (지시 1 의 핵심 — 등록 단추가 바 밑에 깔리지 않는다 — 은 같다). 로그인 안 했으면 로그인 안내(S34).
5. **장바구니의 탭바** — 담은 것이 있으면 목업처럼 탭바가 없고 결제 바만 있다. **비어 있으면 탭바**(목업 S09). 상세·바로 주문·주문 완료도 탭바가 없다.
   🔸 묶음 1 보고의 「결제 바가 탭바를 덮는다」 결정 대기 항목은 이걸로 없어졌다.
6. **결제 바** — 접혔다 펼쳐지지 않는다. 장바구니 바는 「상품 금액 · 주문하기」, 주문서 바는 「○원 결제하기」(P03). 주소·배송 구역이 없으면 단추 글자가 이유를 말한다(예전과 같은 조건).
7. **쿠폰** — P03 처럼 「쿠폰」 한 줄 → 시트 하나에서 보유 쿠폰 고르기와 쿠폰 코드 입력. 🔸 지금 계산 훅(`useCheckoutFlow`)은 **보유 쿠폰과 코드 쿠폰을 같이** 걸 수 있다(예전 화면도 그랬다). 목업은 하나만 고르는 모양이다 — 계산을 바꾸는 일이라 그대로 두었다. 대표님 결정.
8. **쿠폰 코드** — 적용한 코드는 시트 안에 「코드 ○○○ · 빼기」 한 줄. 예전 「제거」.
9. **배송비 딱지** — 「30,000원 이상 무료」(서버의 `free_delivery_min` 그대로). 목업은 「3만원 이상 무료」.
10. **배송지 시트(S11)** — 기본 주소는 고칠 수 없는 칸(회색)으로 보인다(예전과 같다 — 기본 주소는 마이에서 바꾼다).
13. **품절 상품** — 홈 카드는 눌러도 안 열린다(예전과 같다). 검색 결과 줄로는 상세가 열리고, 상세는 목업처럼 「품절」로 담기가 막힌다. (품절 사진의 큰 사진 칸이 비어 보이는 것은 가짜 상품에 사진이 없고 비교 때 외부 사진을 막아서다 — 실제 앱은 분류 기본 사진을 보인다.)
11. **P03 주문서 한 장 — 했다.** 장바구니 = 담은 목록 + 「주문하기」, 주문서 = 주문 상품(여러 개면 한 줄로 접힘 · 누르면 펼침) · 배송지 · 할인 · 결제 금액 · 「○원 결제하기」.
    바로 주문(S12)도 **같은 화면**(제목 「바로 주문」, 상품 1건). 결제 함수(`handlePayment`·`handleQuickPayment`)와 주문에 보내는 값은 **그대로** — 화면만 둘로 나눴다.
    장바구니에서는 배송비를 모른다(주소가 정해져야 정해짐) — 그래서 장바구니 바는 「상품 금액」 이다.
12. **관련 상품의 찜** — 목업처럼 하트가 있고 **실제로 찜이 된다**(로그인 안 했으면 로그인 안내).
