## 🔴 이 묶음에서 찾아 고친 결함

1. 🔴 **(운영 앱에도 있다) 주문내역 카드의 「총 결제금액」이 할인 전 금액이었다.** App 이 주문 목록을 받을 때 `total_price`(상품 금액)를 `totalPrice` 로 넣어,
   쿠폰·포인트·배송비가 빠진 값이 「총 결제금액」으로 보였다. 새 화면은 **실제로 낸 돈 `final_amount`**(없으면 옛 주문이라 `total_price`)를 쓴다 —
   구매 내역 서버(`myPurchases.js`)가 이미 같은 기준을 쓰고 있었다. 시험(`OrderHistory.test.js`)이 이 자리를 지킨다.
2. 🔴 **(운영 앱에도 있다) 온라인 주문 카드에 상품이 하나도 안 보였다** — 주문 목록에는 품목이 없어서 App 이 `items: []` 로 두었다.
   새 화면은 구매 내역 응답의 같은 주문 줄에서 **「농심 메론킥 60g 외 2건」** 요약을 가져와 보인다(누르면 상세).
3. **환불·교환 사유** — 예전 창은 사유 칩과 입력 칸이 **한 값**이라, 칩을 고른 뒤 자세히 적으면 고른 사유가 사라졌다. 고른 사유와 적은 말을 따로 들고 「상품 하자/파손 — 봉지가 터져서 왔어요」로 보낸다.

## 목업과 다르게 둔 곳 — 목록

1. **온라인 카드의 상품 줄** — 목업은 상품 사진·이름·금액 줄. 앱은 **요약 한 줄**(목록 응답에 품목이 없다 — 상세를 열면 사진·금액이 다 나온다). 🔸 목록 응답에 품목을 실을지 — 대표님 결정(서버 일).
2. **매장 영수증의 세금 줄** — 목업은 「과세 물품 · 부가세 · 면세 물품」 세 줄. 서버가 소계·부가세만 주므로 앱은 「소계 · 부가세(포함)」(예전 화면과 같다). 🔸 서버가 과세/면세를 나눠 줄지 — 대표님 결정.
3. 🔴 **취소된 거래** — 목업은 영수증 위 「취소됨」 도장만. 앱은 도장 **+ 맨 위 빨간 상자 「취소된 거래 · 결제 효력 없음 · 취소 시각」** 을 남겼다
   (손님이 폰을 내밀었을 때 계산원이 한눈에 알아야 한다 — 예전 화면이 일부러 둔 것이고 시험이 지킨다). 바코드도 흐리게.
4. **바코드** — 목업은 그림. 앱은 **진짜 거래 바코드(CODE128)** + 숫자(스캐너가 폰 화면을 못 읽을 때 손으로 친다). 어둡게에서도 흰 바탕(스캐너는 반전 심볼을 못 읽는다).
5. **미동의 안내** — 목업처럼 「매장」 탭 안. 「전체」 탭에도 한 줄(「매장 탭에서 동의하면 같이 보여요」)을 두었다 — 예전 화면은 늘 안내를 띄웠는데, 매장 탭을 안 누르면 동의하는 길을 모른다.
6. **순서** — 날짜 최근 것부터(온라인·매장 섞어서). 목업 그림은 순서가 예시다.
7. **환불·교환 단추** — 예전처럼 **배송완료** 주문에만. 진행 띠(대기·승인·완료·반려)의 말은 서버가 주는 말 그대로.
8. **영수증·주문 상세** — 목업처럼 탭바 없이 뒤로만. 「주문내역으로」 단추.
9. **마이 메뉴 이름** — 마이 화면에는 아직 「구매 내역」·「주문내역」 두 줄이 있다(둘 다 이 화면으로 온다). 이름을 「주문내역」 하나로 합치는 것은 마이 화면(P02, 묶음 5) 때.
