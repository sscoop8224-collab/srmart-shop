> 작성 2026-11-11 · 디자인·UI 전면 재정비 **1단계(조사·목업)** 산출물.
> 이 표가 **목업 체크리스트**다. 목업(`C:\srmart\srmart-shop-mockup\index.html`)과 진행표
> (`docs/SHOP_PROGRESS.md`)는 이 화면ID를 그대로 쓴다. 화면ID는 **바꾸지 않는다** — 줄이거나 합치는

>

>
> ⚠️ 쇼핑앱은 **주소(URL)로 화면이 갈리지 않는다.** `App.js` 의 `page` 상태값 하나로 화면을 바꾼다
> (`goToPage('cart')`). 그래서 아래 「경로」 칸은 URL 이 아니라 **`page` 값 · 파일**이다.

## 2. 미뤄 둔 UI 숙제 — 조사 결과

### 2-1. 다크모드 현황

- **켜는 방식**: `ThemeContext.jsx` — 기기 설정(`prefers-color-scheme`)을 따르다가, 손님이 바꾸면 수동(`srmart_dark_manual`).

### 2-3. 상태바·하단 내비 위 회색 여백(safe-area)

`APP_REVIEW_CHECKLIST.md §9` 에 「shop 화면 상/하 회색 여백(홈·상품상세·장바구니)」으로 남아 있던 것. 코드에서 찾은 원인 후보:

1. **바탕이 두 겹이다.** `body` 는 `--gray-100`(#f1f3f5 회색), `.App` 은 `--white`(흰색). `.App` 이 `min-height: 100vh` 라도
   화면마다 자기 바탕을 따로 칠하고(`MyPage` 등 `minHeight: '100vh'` + 회색 `bg`), 내용이 짧거나 끌어당기면(overscroll)
   **`body` 의 회색이 위아래로 드러난다.** `html` 에는 바탕색이 없다.
2. **위쪽 안전영역을 두 번 더한다.** `.App { padding-top: env(safe-area-inset-top) }` 이고 `.header` 도
   `padding-top: env(safe-area-inset-top)` + 높이에 그만큼 더한다(App.css 140~153). 노치가 있는 아이폰(47px)에서는
   헤더 위에 **47px 빈 띠가 한 번 더** 생긴다(그 띠는 `.App` 흰색, 스크롤하면 회색 `body` 가 비친다).
3. **아래쪽**: `.bottom-nav` 가 `padding-bottom: max(env(safe-area-inset-bottom), 8px)` — 안전영역이 0 인 안드로이드에서도 8px 를
   더 띄운다. `.main-content` 아래 여백(`탭바 + 16px`)과 결제 바(`calc(30px + safe-area)`) 계산이 화면마다 따로라 탭바 위에
   회색 줄이 남는 화면이 있다.
4. **안드로이드 시스템 바**: `capacitor.config.ts` 의 `StatusBar.overlaysWebView: false` + 로딩 중 상태바 `#077D3C`(진초록) →
   콘텐츠 뒤 흰색/`#1a1a1a`. 하단 내비바는 **항상 흰색**(2-1). 웹 화면 색과 시스템 바 색이 서로 다른 출처에서 정해진다.

→ 목업은 **상태바 뒤·탭바 아래(홈 인디케이터)까지 화면 바탕(`--bg`)·탭바 색이 그대로 이어지게** 그렸다. 앱 반영 때
`html`/`body`/`.App` 바탕을 한 토큰으로 통일하고 안전영역은 **한 곳(헤더/탭바)에서만** 더한다.
⚠️ 실기기(A12·아이폰) 확인 없이 원인을 확정하지 않는다 — 위는 코드에서 본 후보다.
